# Learning Resources, Tips and Further Reading

This part lists where to study each phase, habits that shorten the timeline, and where to find practice problems and community help. Official documentation is the default source for facts. Use tutorial sites for practice and worked examples, and check them against the official docs when they disagree.

## Acceleration Tips

1. **Run the DSA track in parallel.** Two or three problems a day, starting in week one, is easier to keep up than a block of study later.
2. **Build something at the end of each phase.** A small project shows what you understand. Notes do not.
3. **Use the code review checklist.** The [Java Code Review Guidelines](../code-review-guidelines/java-code-review-guidelines.md) turn vague quality goals into specific checks you can apply to your own code.
4. **Practise on Spring Boot early.** Mini-projects that combine a REST API and a database teach more than reading about each annotation.
5. **Read the official docs.** They are kept current with each release. Blog posts often describe older versions.
6. **Contribute to an open-source project.** Spring, Kafka, and Kubernetes accept documentation and test fixes, which are good starting points.
7. **Do mock system design interviews.** From about week 50, schedule one mock every two weeks.
8. **Pair with a more senior engineer.** Ask them to review one pull request with you and explain the trade-offs they saw.

## Additional Resources

- **Practice platforms:** LeetCode, HackerRank, CodeSignal, InterviewBit, and Educative.
- **Documentation:** the official Java, Spring, and Kubernetes documentation, plus the reference pages for each library you use.
- **Hands-on practice:** your own GitHub projects, and open-source issues labelled for newcomers.
- **Communities:** developer forums and chat servers for Java and Spring, plus Stack Overflow for specific errors.
- **Mock interviews:** Pramp, Interviewing.io, and timed contests on LeetCode.

### Study habits that help

- Write one summary paragraph after each topic, in your own words. If you cannot write it, go back to the source.
- Keep a list of questions you could not answer, and revisit it every week.
- Check every version-specific claim against the release notes for the version you target. Features move from preview to final, and some are withdrawn.
